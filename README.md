# LifeLens · 本地 AI 屏幕活动记录仪

> 一个 **永不联网** 的桌面行为日志：每 20 秒截一帧屏，交给本机的视觉模型看懂"我在干嘛"，
> 再把结果沉淀成 **热力图、时间线、看板、日记、问答** 五个视角。

**数据全程不出本机。** 截屏、视觉推理、汇总、检索全部在本地完成，
不调用任何云端 API、不上传任何字节 —— 就连 AI 也是本机 Ollama 里的 4B 视觉模型。

一个 Electron 桌面应用：定期截屏，调用本机 **Ollama** 运行的视觉模型
**`qwen3-vl:4b-instruct`** 分析画面，用**简短的 5 句话**总结"用户正在做什么"，并把结果
按**月份建目录、按小时建 JSON 文件**持久化到本地。

## 设计要点

| 维度 | 取舍 |
| --- | --- |
| 隐私 | 金融/密码类窗口默认**整帧跳过**（连标题都不记录），可被 `privacyExclude` 扩展 |
| 算力 | 默认 **CPU 推理**（`num_gpu_layers: 0`）+ 全局推理互斥，把 GPU 显存让给你正在跑的其它 AI 任务 |
| 调度 | **事件驱动**截屏（窗口切换/空闲暂停/停留上限），替代固定轮询 —— 日均从 4320 帧降到约 150 帧 |
| 分析 | **分层**：标题已能说明问题时跳过视觉模型，仅图像/视频/游戏类才真正调用推理 |
| 存储 | 月/小时分片 JSON + 代表帧去重 + 滚动清理，磁盘从约 1.3GB/天 压到约 50MB 稳态 |
| 问答 | **RAG-lite**：模型自己规划时间范围与关键词的多轮检索（≤3 轮，无向量库） |

## 功能

- ⏱ 定时截屏（默认 20s，可在界面调整，最小 5s）
- 🖥 整屏捕获（Electron 内置 `desktopCapturer`，无需第三方截屏库）
- 🧠 本地视觉模型分析（Ollama，零云端泄露，隐私友好）
- 📁 数据组织：
  - 按月建文件夹：`data/2026-07/`
  - 截屏存于：`data/2026-07/screenshots/2026-07-29-19-06-40.png`
  - 每小时一个 JSON：`data/2026-07/2026-07-29-19.json`
- 📝 每条记录包含：时间、对应图片绝对路径、使用的模型、活动总结（整段 + 分句）、分析状态
- 🧩 **十分钟结构化汇总**：每 10 分钟把该窗口内所有截屏记录聚合，结合上一个 10 分钟的汇总，
  由模型产出结构化结果（项目名称 / 分类 / ~1000 字描述 / 软件列表 / 可能遗漏的待办）；
  与上一个窗口连续的活动会**复用相同项目名**（如“写《2026年中报告》”）。
- 📊 **“动态”标签页**：类 GitHub 热力图（每点 = 10 分钟，按活动类型着色，点击查看详情）+
  可纵向无限滚动的时间线（项目名 + 描述 + 软件标签）+ 按项目名 / 软件 / 日期筛选。
- 📓 **“日记”标签页**：日历选择任意一天（默认打开前一天），基于当天所有 10 分钟汇总做一次
  “二阶汇总”，由模型生成当日日记（简短总结 / 主要事项三件 / 高光时刻 / 待办 / 优化建议 /
  温馨提示）；打开页面时自动扫描并补齐历史未生成的日记，生成中显示“日记生成中（队列 N）”。
- 📈 **“看板”标签页**：按 天 / 周 / 月 / 年 切换，多维可视化——活动类型时长占比饼图、
  软件出现次数排名、项目专注时长统计、按小时活动分布堆叠图、日维度趋势折线图，并附统计卡片
  （总时长 / 已分类时长 / 主要类型 / 涉及项目 / 涉及软件 等）。
- 💬 **"问答"标签页**：基于本地记录（20s 原始总结 / 10 分钟结构化汇总 / 日记）的检索增强问答。
  先让模型自行规划“在哪个时间范围、用哪类汇总、搜什么关键词”，执行 agentic 检索（最多 3 轮，
  本轮无新增片段即提前停止以节省资源），再基于检索到的相关片段作答；检索过程与最终答案都会在界面展示。
- 💾 **存储防爆盘（三层省空间，默认开启）**：
  1. 截图改 **JPEG（质量 70）+ 降分辨率（最大宽度 1600px）**：从全分辨率无损 PNG 改为有损压缩并缩小，
     对模型识别几乎无影响，单张大幅变小；
  2. **每 10 分钟仅保留一张“代表帧”**（`keepRepresentativeOnly`，默认开）：其余 20s 帧只分析、不落盘，
     该桶内所有记录共用一张图，截图数再降约 30 倍；
  3. **旧截图自动清理**（`screenshotRetentionDays`，默认 7 天）：超过天数的截图文件自动删除，
     文本记录（record/summary/diary）不受影响，仅损失“回看某时刻真实画面”。
  - 监控页“存储与空间”卡片实时显示：数据目录占用、截图/记录占比、近 1 小时增长、预估每日新增、
    磁盘剩余空间、保留策略，以及“若不清理由当前速率多久爆满”的预警（磁盘剩余靠 `fs.statfsSync` 实读）。
  - 实测效果：从“每天约 1.3 GB 且无限增长” → 新策略稳态约 **50 MB 封顶**。

## 存储相关配置（设置页可改）

| 配置项 | 默认 | 说明 |
|--------|------|------|
| `screenshotQuality` | 70 | JPEG 质量 0-100，越小越省空间 |
| `screenshotMaxWidth` | 1600 | 截屏最大宽度(px)，0=原分辨率 |
| `screenshotRetentionDays` | 7 | 旧截图保留天数，0=永久保留 |
| `keepRepresentativeOnly` | true | 每 10 分钟仅保留一张代表帧 |

> 提示：若 D 盘仍紧张，把 `数据目录`（`dataDir`）指到更大的盘/外置盘是最直接的缓解。
- 🎛 内置控制面板：开始/停止、最新截屏预览、活动摘要、设置、运行日志、Ollama 连通性检测，
  以及顶部“汇总中（队列 N）”实时标记。

## 前置条件

1. **Node.js 18+**（本项目用 22 验证；需要全局 `fetch`）。
2. **安装并运行 [Ollama](https://ollama.com)**。
3. **拉取视觉模型**（一次即可）：
   ```bash
   ollama pull qwen3-vl:4b-instruct
   # 若你的标签是 qwen3-vl:4b，请在界面“设置-模型名”里改为 qwen3-vl:4b
   ```
4. 确认 Ollama 服务在 `http://127.0.0.1:11434`（默认）。若改了端口/地址，在界面设置里改。

## 安装与运行

```bash
# 安装依赖（Electron）
npm install

# 启动应用
npm start
```

启动后：

1. 点 **“检测 Ollama”** 确认模型已安装且可达（不通会给出 `ollama pull` 提示）。
2. 点 **“开始”** 即可。最新截屏与模型总结会实时显示在界面上。
3. 数据会写入项目下的 `data/` 目录，结构见上。

> **Ollama 不用开桌面 GUI。** 应用启动时会自动探测 `127.0.0.1:11434`，
> 服务没起来就自己拉一个无界面的 `ollama serve`，省下图形外壳那几百 MB 常驻内存。

## 打包为单文件 exe

```bash
npm run dist      # 产物：dist/LifeLens.exe（portable，免安装）
```

便携版会把数据目录放在 **exe 所在安装目录的 `data/`**（不是 `%TEMP%`、也不是 AppData），
所以多条历史记录可以随身携带、不会被系统清理工具误删。
桌面快捷方式丢了的话，双击仓库里的 `recreate-lifelens-shortcut.cmd` 可重建。

## 已知坑（Windows / 便携版）

这些是实际踩过的，按现象查会省很多时间：

| 现象 | 根因 | 处理 |
| --- | --- | --- |
| 开机弹 cmd 窗口 / 桌面图标双击没反应 | 便携版 `process.execPath` 永远指向 `%TEMP%` 下的解压目录，把它写进自启或快捷方式必然失效 | 用 `PORTABLE_EXECUTABLE_DIR` 重新定位（见 `resolveSelfPath()`） |
| 白屏 + 内存暴涨 | 单实例锁写成"先抢锁、失败才杀旧进程"，留下竞态窗口 → 双实例并存 → 渲染进程 OOM | 启动时先 `killOtherInstances()` 清场，再单次 `requestSingleInstanceLock()` |
| 窗口标题里中文变乱码 | PowerShell 默认 GBK(936) 输出，Node 侧按 UTF-8 解管道 | PowerShell 侧 base64 编码后再传；落库前 `sanitize()` 剥离 U+FFFD |
| 开了之后其它 AI 项目跑不动 | Ollama 默认 `num_gpu_layers` 取最大值，把整个模型塞进显存 | 每个请求显式 `num_gpu_layers: 0` + 全局推理互斥（见 `ollamaClient.js`） |
| 构建成功但运行时报 `MODULE_NOT_FOUND` | electron-builder 的 `build.files` 是**显式白名单**，新增顶层模块不会自动进 asar | 在 `package.json` 的 `build.files` 里补登记，打包后再抽样核验归档 |
| 打包卡在 `nsis.7z` 删除失败 | 某些 CLI 环境注入了把 `fs.unlink` 换成回收站操作的 shim | 打包时清掉该注入：`env -u NODE_OPTIONS npm run dist` |

## 十分钟汇总 & 动态页 说明

- **触发与排队**：应用运行时会启动一个汇总调度器，每当一个 10 分钟窗口结束就把它加入队列；
  处理是串行的（避免并发打爆本地模型）。应用启动时还会扫描当月历史，把“有记录但未汇总”的
  时间段（backlog）全部排队依次处理——所以**之前漏掉的十分钟段会在运行后自动补齐**。
- **UI 标记**：顶部显示“汇总中（队列 N）”徽标，队列清空后自动消失。
- **项目连续性**：汇总提示词会带上一个窗口的项目名，要求模型在活动连续时**复用完全相同的名称**
  （如“写《2026年中报告》”“玩《原神》”），方便跨窗口归并同一件事。
- **热力图**：每格 = 一个 10 分钟桶，颜色对应活动类型（娱乐/工作/学习/社交），斜纹格表示“待汇总”，
  浅灰表示“无数据”。点击有数据的格子可查看该时段的汇总或截屏活动。范围可在 12h/24h/48h/7天 间切换。
- **时间线**：按时间倒序展示每个已汇总窗口的项目名、分类、描述（可展开）与软件标签；
  向下滚动自动加载更早的；可按项目关键字、软件、日期筛选。点软件标签即按该软件筛选。

## 日记页 & 看板页 说明

- **日记（二阶汇总）**：在“日记”标签页，日历默认打开**前一天**；点任意有记录的日子查看当日日记。
  日记由模型基于当天**所有 10 分钟结构化汇总**再做一次总结，产出 6 个部分：简短总结、主要事项
  （最重要的三件事）、高光时刻、待办、优化建议、温馨提示。打开日记页时会自动扫描并排队所有
  “有汇总但无日记”的历史日期（跨月也会扫），在后台依次补齐——顶部显示“日记生成中（队列 N）”，
  生成完成自动刷新。已生成的日子日历上会有“有日记”标记。
- **看板（多维可视化）**：在“看板”标签页，可切换 **天 / 周 / 月 / 年** 四种粒度，图表会自动重算。
  包含图表：①活动类型时长占比饼图 ②软件出现次数排名（横向条形）③项目专注时长统计
  （横向条形）④按小时活动分布堆叠图 ⑤日维度趋势折线图；上方还有统计卡片（总时长 / 已分类时长 /
  未分类时长 / 有数据天数 / 主要类型 / 涉及项目 / 涉及软件）。切换粒度或刷新时旧图表实例会被销毁，
  避免内存泄漏。无数据时统计卡显示“—”或“0 分钟”，不会报错。

## 问答页 说明（agentic 检索增强）

- **流程**：在“问答”标签页输入问题（Ctrl/⌘+Enter 发送），应用先让本地模型**规划检索**——
  自行决定时间范围（from/to，默认最近两周、硬上限 60 天）、用哪一类数据源
  （record=20s 原始总结 / summary=10 分钟汇总 / diary=日记）、搜什么关键词；执行检索后，
  把已收集片段摘要回给模型，模型可**再补充检索最多共 3 轮**。若某轮未新增任何片段会提前停止，
  避免重复检索浪费资源。最后基于去重后的相关片段由同一模型作答。
- **搜索方式**：为保持简单，未引入向量库，采用**关键词命中**（子串匹配，中文不依赖分词库）；
  每条记录/汇总/日记按可检索文本（activity/project/category/description/software/brief 等）匹配，
  命中后按时间倒序、命中数降序返回，单查询上限 40 条、回答上下文上限约 20000 字。
- **开放式回顾问题**（如“我最近在干什么”“今天做了什么”“总结一下这几天”）：这类问题没有具体
  实体关键词，因此**允许空关键词查询 = 拉取该时间范围内的全部内容**（整体回顾）；若模型一轮都没给出
  有效查询，会自动兜底拉取最近 3 天的 record/summary/diary 全部内容，保证至少能基于最近记录作答，
  而不是零检索就结束。
- **界面**：展示每一轮检索（源 / 范围 / 关键词 / 命中数）与“已足够停止”标记，以及最终答案。

## 隐私声明

LifeLens 记录的是**你自己屏幕上的一切**，这个项目在设计上做了这些约束：

- 分析用本地 Ollama 模型，无任何云端调用；
- `privacyExclude` 默认跳过金融 / 密码类窗口（`支付宝`、`银行`、`1password` 等），可自行扩展；
- 数据只写本地 `data/`，仓库的 `.gitignore` 默认排除它，避免误提交；
- 开源前请务必自查：不要把你的 `data/`、截屏或任何个人日志提交进仓库。

> 屏幕活动属于高度敏感数据。若你在公共设备上使用，建议先关掉 `storeScreenshots`，只保留文字总结。

## 注意事项

- **性能**：4B 视觉模型单次推理通常数秒，已做“上轮未结束则跳过本轮”的防堆积保护；
  若推理经常超过 20s，建议在设置里把间隔调大（如 30–60s）。
- **隐私**：所有截屏与分析均在本地完成，不上传任何服务器。
- **磁盘**：截屏会持续占用空间，建议定期清理 `data/` 或配置到非系统盘目录。
- **多显示器**：当前捕获主显示屏整屏；如需指定显示器可改造 `capture.js` 的源选择逻辑。
